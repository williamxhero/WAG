# Issue tracker: GitHub

Issues and specs for this repo live as GitHub issues. Use the `gh` CLI for all operations.

## Conventions

- Create, read, update, comment on, label, and close issues using `gh issue`.
- Infer the repository from the current clone and its GitHub remote.
- Pull requests are not a triage request surface.
- When a skill says “publish to the issue tracker,” create a GitHub issue.
- When a skill says “fetch the relevant ticket,” read the issue and its comments.
- Skills using maps and child tickets should use GitHub sub-issues and native issue dependencies when available, with task-list and `Blocked by:` fallbacks otherwise.
