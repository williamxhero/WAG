## Public seam and safe integration contract

`createProviderHttpTransport({ name, credentials, tariff, timeoutMs = 5000, maxRequestBytes = 16384 })` returns a frozen async function accepting the existing adapter's `{ endpoint, api, body, maxResponseBytes, signal }`. It returns `{ status, body }`, plus `tencentVersion` only for Tencent documented-max 2xx result envelopes. This bounded posterior field is exactly `lite`, `standard` or `flagship`; missing/unknown/malformed result versions reject as sanitized `provider_version_mismatch`. Invalid JSON rejects as `invalid_response`. Genuine Tencent API error envelopes with a nonempty string Error.Code have no result version/diagnostic and remain delegated to the unchanged adapter's sanitized authentication/rate-limit/upstream classification; malformed error codes reject. Non-2xx bodies are discarded without parsing/diagnosis, redirects are rejected, and networking/parser failures have only a fixed sanitized `message`/`kind` (no cause). No environment or file reads, proxy/global-agent reuse, retries, logging or automatic enablement. The optional `request` and `now` dependencies are TRUSTED offline seams, not untrusted runtime configuration. Do not expose them to callers.

Bounds: POST JSON only; exact endpoint strings (no query/fragment/custom port); UTF-8 request default 16 KiB, configurable 1–65536 bytes; response caller limit 1–1048576 bytes; incoming HTTP headers capped at 16 KiB by Node's parser. Outgoing headers are fixed names/values plus printable ASCII credentials of at most 4096 characters, bounding total header bytes below 16 KiB (SecretKey never appears in a header). Absolute total deadline 1–30000 ms, including TLS handshake and slow trickles, not an idle timeout. Native certificate-chain AND hostname validation remain enabled. Every failure/abort destroys response/request; success uses a nonpooled agent and closes the socket. Both the supplied body and actual serialized JSON are feature-validated before signing/sending. Unsupported compression is rejected, never expanded.

Configuration shapes:
- Baidu: `credentials: { apiKey }`, `tariff: { confirmed: true, freeQuotaOnly: true }`.
- IQS: `credentials: { apiKey }`, `tariff: { confirmed: true, version: 'CNLiteBasic', costCents }`.
- Tencent approved default selection: `credentials: { secretId, secretKey }`, `tariff: { confirmed: true, version: 'documented-max', costCents: 3 }` (or a higher safe integer). Retained alternative: `tariff: { confirmed: true, version: 'lite', costCents }`, cost >=2.

`confirmed` means an integration owner confirms the applicable conservative billing bound, not merely that keys exist. Documented-max confirmation uses the approved documented upper bound; no account-lite prerequisite. Exact lite/CNLiteBasic paths still require those version-specific confirmations. Unknown tariffs, explicit standard/flagship tariff modes, IQS paid contents and other engine variants fail closed. TC3 signs exact UTF-8 POST `/` payload, canonical `content-type:application/json` and `host:wsa.tencentcloudapi.com`, signed headers `content-type;host`, UTC date/`wsa`/`tc3_request` key ladder; action `SearchPro`, version `2025-05-08`. Dummy golden is `7bf4126047eaf16a06f5328e1da13bad97087219cea0de4863e069ebed9f27d1` for timestamp1551113065 and the test's Chinese payload.

**Never call the transport directly in production.** It does not own the ledger or enforce quota. Existing `createBudgetedProviderSearch` must reserve before `adapter.search`, using the frozen transport's `estimatedCostCents` or a higher confirmed bound. Its default 1/2-cent floors do NOT automatically discover the transport estimate. Explicit integration (illustrative, not server wiring):

```js
// transports: Map of explicitly constructed/confirmed transports; budget: persistent ledger.
const providers = [...transports].map(([name, transport]) =>
  createProviderAdapter({ name, enabled: true, transport,
    ...(name === 'tencent' ? { site: 'mp.weixin.qq.com' } : {}) }));
const search = createBudgetedProviderSearch({ providers, budget,
  estimateCostCents: name => {
    const transport = transports.get(name);
    if (!transport) throw new TypeError('provider transport required');
    return transport.estimatedCostCents; // Use a higher verified bound if needed; never lower.
  } });
```
