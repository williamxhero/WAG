# SPEC #74 opt-in pool paired production probe (2026-10-13)

## Scope and method

Read-only HTTP requests to the already-running SearXNG `/search` endpoint. No settings, overlay, systemd environment, engine enabled/disabled state, proxy, timeout, deployment, or limit was changed. The `pool` arm only added the native `engines=` query parameter; it did not configure the production gateway pool.

- Three fixed query classes: general (`中国 经济 政策`, zh-CN), news (`SearXNG documentation`, en), strict day (`Federal Reserve interest rate decision`, en, `time_range=day`).
- 20 paired samples per class; each pair repeated the same query for baseline (no `engines`) and pool (specified `engines`), requests serialized and alternating arm order by pair.
- 120 total requests, 0 HTTP/client errors, each request records UTC timestamp, query parameters, duration, result count, result-producing engines, and unresponsive engines.
- Raw JSON: [`wag-pool-ab20-20261013.json`](wag-pool-ab20-20261013.json); 69,753 bytes, 120 observations. It is production-origin evidence, not a synthetic fixture.

Failure classifications are retained per observation in the raw JSON. The dominant failures were quark CAPTCHA/suspension and yandex timeout/suspension. `chinaso news` did not produce results in the treatment window.

## Acceptance assessment against SPEC #74 §5.1

The run satisfies the measurement protocol (20 observations per arm and query class, serialized, raw evidence retained), but **does not satisfy the supply-quality targets**:

- General zero-result target `<5%`: observed 90% baseline / 85% pool — fail.
- English news zero-result target `<10%`: observed 100% / 70% — fail.
- Strict-day zero-result target `<20%`: observed 100% / 100% — fail.
- `>=2` result-producing engines: general target `>=80%`, observed 10% / 15% — fail; strict-day stretch `>=50%`, observed 0% / 0% — fail.
- Single-query p95 target `<=4000ms`: all six arms pass this sample window; this does not compensate for the unmet zero-result and engine-diversity targets.

The treatment arm has a directionally lower zero-result rate for news only. It is not a production improvement claim: all target rates remain unmet, pool configuration was not installed in the gateway, and upstream engine supply is unstable.

## Decision and boundary

Keep the production pool unconfigured. This read-only experiment does not justify a production change, does not meet the SPEC's strict-day requirement, and does not unlock the external supply needed to pass. No security gate, user-controlled production configuration, or external authorization was bypassed. SPEC #74 remains open pending materially changed engine supply or an authorized decision on an external source/configuration; #49 and #60 retain the measured availability/quality follow-up.
